# Проверка конкурентных операций в Apache JMeter

План `routes-concurrency.jmx` использует HTTP Request, Cookie Manager, Synchronizing Timer и встроенный в JMeter Groovy. Проверено на Apache JMeter 5.6.3. Используйте отдельную тестовую базу: план регистрирует пользователей, создаёт и удаляет маршруты, а часть тестовых данных и история остаются в БД.

## Запуск из корня проекта

```powershell
jmeter -n -t jmeter/routes-concurrency.jmx -l target/lab2.jtl -j target/lab2-jmeter.log -Jhost=localhost -Jport=8080 -Jusers=10 -e -o target/jmeter-report
python jmeter/check_results.py target/lab2.jtl
```

На Windows укажите путь к `jmeter.bat`, если он отсутствует в `PATH`. Для каждого запуска используйте новый путь к JTL и новый либо пустой каталог HTML-отчёта. HTML-отчёт открывается из `target/jmeter-report/index.html`. В GUI можно открыть JMX и нажать Start. Параметры настраиваются через `-Jhost`, `-Jport`, `-Jusers` (от 2 до 100) и необязательный `-Jrun` (уникальный для БД токен из 1–20 латинских букв или цифр). По умолчанию токен генерируется заново. Путь приложения в плане — `/routes`.

Группы запускаются последовательно. Внутри группы каждый поток регистрирует отдельного пользователя и получает собственный cookie. CRUD выполняют 10 потоков по умолчанию. В гонках участвуют 8 потоков, в смешанной гонке PUT/DELETE — 2. Таймер перед каждым конфликтующим действием собирает потоки вместе. Результаты проверяются через HTTP и повторное чтение состояния сервера.

| Группа | Проверки |
|---|---|
| CRUD, импорт и история | Создание, редактирование и удаление маршрутов. Согласованность `total` и последней страницы. Multipart-импорт трёх записей. Дубликат во второй записи отклоняется, созданные первой записью маршрут, координаты и локация откатываются. Пользователь видит обе свои операции и счётчик только у успешной. |
| Гонки уникальности | Один `201` и семь `409` для пары координат, названия локации, названия маршрута и одинакового импортируемого файла. Повторное чтение подтверждает ровно один объект каждого вида. |
| Гонки за маршрут | PUT/PUT даёт один `200` и семь `409`, версия увеличивается ровно на один. DELETE/DELETE даёт один `204`, последующий GET — `404`. Смешанная гонка с одинаковой исходной версией даёт PUT `200` + DELETE `409` либо PUT `404` + DELETE `204`. |

Ожидаемые отказы проходят assertions. Команда `check_results.py` проверяет столбец `success` и наличие последней проверки. Она возвращает ненулевой код при сбое, даже если процесс JMeter завершился с кодом 0.

Сохранённые результаты прогонов на [10 пользователей](results/lab2-10.jtl) и [20 пользователей](results/lab2-20.jtl) можно проверить той же командой. Для построения HTML-отчёта из сохранённого JTL используйте `jmeter -g jmeter/results/lab2-10.jtl -o target/jmeter-report` и укажите новый или пустой каталог вывода.

## Дополнительная проверка API

Зарегистрируйте `boss` и `labadmin` с паролем `password123` на тестовой БД, затем перезапустите приложение с `APP_ADMINS=boss,labadmin`. Скрипт проверяет права доступа к истории, валидацию и гонки двух администраторов.

```powershell
$env:BASE_URL = 'http://localhost:8080/routes/api'
python jmeter/concurrency_check.py
```
